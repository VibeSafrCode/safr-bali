# Отдельный пакет: защищённый гостевой чат сайта

Founder в primary01 выбрал «Нужен защищённый гостевой чат отдельным пакетом» и поручил согласовать с05: посетитель ведёт диалог в окне сайта, Founder получает сообщения через Telegram-бота и отвечает оттуда; отдельный бот «Чат на сайте» допустим при необходимости.05 проверил поручение и согласовал архитектуру30Oct. Этот пакет следует после Bali Support → нейтральный бот → визовый агент и не блокирует их независимую подготовку. Текущий результат — в [CURRENT_STATE](CURRENT_STATE.md).

## Решение

Использовать существующий Saffron для Founder и Bali Support, WebConversation/WebMessage, web outbox, штатные Reply/History и server actor ACL. Метка «Сайт» связывает уведомление с конкретным диалогом. Новая CRM/backend/очередь или отдельный bot token для первой версии не нужны. Отдельный бот остаётся возможной будущей организацией потока, без создания сейчас.

Текущая `POST /chat/guest` — приём формы, не гостевая identity. Account `GET /chat` требует зарегистрированного User. `conversation_id`, retry UUID, имя и контакт не являются доказательством владения и не связывают посетителя с существующим клиентом.

## Минимальная реализация

1. Отдельная guest session: случайный серверный секрет, в БД только hash, expiry/revocation; привязка к одному диалогу и разрешённому сайту. Отдельная host-only Secure/HttpOnly/SameSite cookie; секрет не попадает в URL, localStorage или логи. Переиспользовать существующий session/hash/TTL шаблон; начальный срок — действующие30дней. Завершение чата на устройстве отзывает доступ, историю не удаляет.
2. Сессию создать без обращения. Первый POST атомарно создаёт/привязывает conversation, message и существующий outbox; следующие сообщения идут в тот же conversation. Идемпотентность привязана к проверенной guest session + request key, конфликт тела отвергается. Конкурентные первые запросы не создают два диалога.
3. Read/send проверяют текущую сессию; write требует точный разрешённый public-site Origin и CSRF. Не расширять аккаунтную защиту wildcard. Лимиты сессий/сообщений, private/no-store ответы, отзыв/expiry до чтения, записи и replay.
4. Ответ Founder/Support — прежний WebMessage, видимый гостю через защищённый GET. Для гостя выбрать web-only возврат, без несуществующего Telegram recipient и ложного failed. Main/Yoga/account transport сохраняются. «Сохранено в чате» не означает «прочитано».
5. В фактически обслуживаемом Astro-окне: текстовая история, поле ответа, безопасное отображение текста. Загрузка при открытии/после send и короткий опрос только при открытом чате и видимой странице, один запрос за раз; отмена/проверка актуальности при закрытии или смене сессии. Без WebSocket-сервиса и постоянного фонового polling.
6. Reload того же браузера с действующей cookie восстанавливает диалог. Очистка cookie, expiry или другое устройство не дают доступ к прошлой истории; показать понятное сообщение. Старые guest leads автоматически по контакту не присоединять.

## Достаточная приёмка

- Гость A → Saffron → ответ Founder/Support → тот же сайтный чат; reload сохраняет историю без Telegram login.
- Гость B/нет proof/чужой conversation_id или Origin/expiry/revoke не читают и не изменяют A, включая replay. Internal notes и чужие поля не выдаются.
- Retry, timeout и два первых POST не дублируют conversation/message/outbox. Защита неизвестного Telegram-send исхода сохраняется; exactly-once transport не обещается.
- Проверить только затронутые существующие Main/Yoga/account сценарии.
- Один локальный UI-сценарий mobile/desktop: доступное поле и фокус, HTML как текст, скрытое/закрытое окно не опрашивает, устаревший ответ другой сессии не подменяет историю. Нужен адресный независимый design/security review изменённого окна.

Вне первого пакета: вложения/PDF, объединение по контакту с CRM-клиентом, межустройственное восстановление, новый бот, рассылки и универсальная платформа. Прямое дополнение Founder 01.11.2026 «Пуш деплой комит сверка документов» разрешает commit/push/CI и выпуск этого гостевого пакета; условия сохранности, проверки миграции и обычные tool approvals сохраняются. Старые technical windows и использованные операторы другого scope не используются. Фактические результаты — в CURRENT_STATE.
