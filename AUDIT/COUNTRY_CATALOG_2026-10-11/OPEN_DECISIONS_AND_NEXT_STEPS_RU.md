# Решения и минимальная последовательность продолжения

## Нужны материальные ответы / входные данные

1. Передать полный `SAFRWAY_DOCUMENTS_ALL_10_LOCALES_CODEX_2026-10-09.zip`, либо подтвердить, что он недоступен и Documents остаётся отдельным будущим этапом. Не восстанавливать переводы по памяти/MD без full JSON.
2. Для Business/Documents/new international services подтвердить реального исполнителя, что именно SAFRWAY продаёт, fixed price или approved individual quote и применимый passport/residence/application context. Наличие текста/перевода и просьба принять пакет не заменяют факт существования операции.
3. Если всё-таки требуется переименовать пять existing candidates, выбрать canonical явно после source/HTTP/backlink reconciliation. Сейчас безопасный вариант — сохранить существующие; обе версии каждого URL 404, массовых redirect оснований нет.
4. Подтвердить приоритет следующей реализации: сначала клиентская chrome/контекст или выпуск готового Business/Documents после gate-проверок. Этот аудит не открывает выпуск.

## Codex может подготовить после согласованного scope

1. Сверить независимый GPT audit с данным baseline, не возвращаться к 78d3ec2 и не повторять уже выпущенные визовые batches.
2. Устранить semantic association gap в изолированном planning draft, добавить focused negative tests, не ослабляя frozen histories.
3. **Выполнено в documentation-only sync:** canonical current-state/backlog и входные summaries обновлены по receipts. Astro67e / App36fe / source baseline3659 / последующий docs Git commit — разные версии, не основание пустого redeploy.
4. Детерминированный public model context: section/country/region/Service.slug из существующих данных, а не defaults «Бали/visa». Сохранить current leads/analytics IDs и не тестировать реальными customer messages.
5. Использовать существующую language detection/switcher. Закрыть client-only ten-language chrome, без перевода услуг заново и без admin localization.
6. Импортировать отсутствующий Documents full JSON, сверить RU revisions, факты, FAQ/CTA/SEO/link tables, IDs/pricing bindings. Не создавать legalization/corporate_docs автоматически до сверки source identities.
7. Business/Documents QA с Designer в одном существующем браузере пользователя: mobile/tablet/desktop + AR RTL/CJK. Если контроля нет — NOT_RUN, а не запускать сторонний браузер.
8. Включать nav группами только на actual public target. Assistant/guides/insurance/exchange/housing/visa chooser остаются, пока дополнительные группы не готовы.
9. New world/country pages — отдельные operational/editorial waves после approved service/quote/eligibility. Country context не создаёт новую бизнес-операцию.
10. Только после явного release gate: contributor reconciliation и checklist, scoped commit/CI, push, exact artifact deploy, version/rollback verification. Сначала local implementation, затем Git, затем production — не смешивать.

## Не запускать по этому аудиту

- Остановленные SEC-NEXT, native/Admin-date, Yoga bot/product, Referral economy, avatars, protected storage activation.
- Массовые country/Schengen SEO landing pages, invented service prices/legal promises.
- Любые сообщения клиентам, формы на live customer data, платежи, production writes или FX publication.

Отмеченные IMEI/K-ETA/Australia/Schengen/E28A/E33G-family темы требуют отдельной актуальной проверки официальных источников и применимости. Этот технический аудит не подтверждает правовые утверждения пакета.
