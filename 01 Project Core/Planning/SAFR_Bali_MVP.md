# SAFR Bali — MVP первого запуска

Дата фиксации: 2026-06-29  
Проект: SAFR Bali / Na Bali Team  
Цель MVP: быстро запустить Telegram-first систему, которая приводит заявки, фиксирует рефералов, начисляет SAFR Points и готовит фундамент для Mini App, сайта и будущего токена.

---

## Актуализация на 2026-07-28

Первоначальный Telegram-first MVP запущен и используется в production.

Готово:

- Telegram-бот и backend;
- PostgreSQL, миграции и защищённый API;
- четыре направления и deep links;
- глобальная неизменяемая реферальная связь;
- кабинеты пользователей и менеджеров;
- маршрутизация вопросов по стране, региону и услуге;
- внутренние заметки и чат менеджеров по клиенту;
- сайт `safrway.online`;
- Telegram Mini App `app.safrway.online`;
- Cloudflare Tunnel и HTTPS.

Частично готово:

- SAFR Points отображаются, но полный автоматический цикл начислений и списаний
  ещё развивается;
- заявки и купленные услуги читаются из backend, но полная CRM-автоматизация
  остаётся следующим этапом;
- Mini App содержит кабинет и каталог с полностью внутренней навигацией;
- сайт раскрывает страны, разделы, услуги и материалы на отдельных URL;
- локально подготовлены Telegram Web Login, web-кабинет и диалог с менеджером;
- локально Mini App переведён на независимые экраны без якорной прокрутки.

Не готово:

- автоматическая оплата;
- полноценное управление reward rules из интерфейса;
- QR-коды партнёров;
- marketplace и исполнители;
- VK и Android-клиенты.

Разделы ниже сохраняют исходные продуктовые требования MVP. Фактические
технические статусы ведутся в `06 Development/docs/MVP Task List.md`.

## 1. Что мы делаем в MVP

MVP — это не полный маркетплейс и не готовая токен-экономика.

MVP — это первая рабочая версия системы, которая позволяет:

1. пользователю зайти в Telegram-бота;
2. выбрать нужную услугу;
3. оставить заявку;
4. администратору увидеть заявку;
5. зафиксировать, кто пригласил клиента;
6. начислить бонусы по 1, 2 или 3 уровню;
7. показать пользователю баланс SAFR Points;
8. показать партнёру его ссылку и QR-код;
9. централизованно менять правила начислений;
10. не пересчитывать старые баллы при изменении правил.

Главный результат MVP: система уже может использоваться для реальных клиентов и реальных продаж.

## 3. Что НЕ входит в MVP

Чтобы не уйти в бесконечную разработку, в первый запуск не входит:

- полноценный Avito-маркетплейс;
- карточки вилл с фильтрами;
- задания для исполнителей;
- автоматические выплаты;
- настоящий SAFR Token;
- DEX / рынок токена;
- веб-админка;
- сложный рейтинг исполнителей;
- escrow;
- мультиязычность;
- сложная CRM;
- автоматическая юридическая документация;
- полноценный сайт с SEO-блогом.

Эти идеи фиксируются в roadmap, но не блокируют первый запуск.

## 5. SAFR Points в MVP

Стартовый внутренний номинал:

> 100 SAFR Points = $1 внутренней скидки.

Публично можно писать проще:

> SAFR Points можно использовать на скидки, бонусы и услуги внутри SAFR Bali.

Стартовые начисления можно поставить такие:

| Услуга | Direct | Balanced | Network |
|---|---:|---:|---:|
| Виза | 2500 / 0 / 0 | 1500 / 500 / 200 | 500 / 500 / 500 |
| Продление | 1000 / 0 / 0 | 700 / 300 / 100 | 300 / 300 / 300 |
| Консультация | 500 / 0 / 0 | 300 / 100 / 50 | 100 / 100 / 100 |
| Подбор жилья | 5000 / 0 / 0 | 3000 / 1000 / 500 | 1000 / 1000 / 1000 |
| Трансфер | 300 / 0 / 0 | 200 / 100 / 50 | 100 / 100 / 100 |
| Байк | 500 / 0 / 0 | 300 / 100 / 50 | 100 / 100 / 100 |

Цифры стартовые. Их можно менять через админку.

## 6. Партнёрские режимы MVP

### 6.1. Direct

Для личных рекомендаций.

Смысл:

> Партнёр получает максимум за прямого клиента, но не получает в глубину.

Пример по визе:

- 1 линия: 2500 Points;
- 2 линия: 0;
- 3 линия: 0.

### 6.2. Balanced

Универсальный режим.

Смысл:

> Партнёр получает нормально за прямого клиента и немного за второй и третий уровень.

Пример по визе:

- 1 линия: 1500 Points;
- 2 линия: 500 Points;
- 3 линия: 200 Points.

### 6.3. Network

Для кафе, QR-кодов, ресторанов, байкеров, водителей и пассивных точек.

Смысл:

> Партнёр получает меньше за прямого клиента, но может заработать на глубине сети.

Пример по визе:

- 1 линия: 500 Points;
- 2 линия: 500 Points;
- 3 линия: 500 Points.

## 7. Главное правило начислений

Начисления не должны пересчитываться задним числом.

Если админ изменил правила, это влияет только на новые заказы.

Пример:

1. 29 июня за визу действует ставка 2500 Points.
2. Клиент оформил визу.
3. Партнёр получил 2500 Points.
4. 30 июня админ поменял ставку на 1500 Points.
5. Старые 2500 Points остаются.
6. Новые заказы начисляются уже по 1500 Points.

Для этого в points_ledger должна сохраняться операция с rule_id и snapshot начисления.

## 8. Жизненный цикл заявки

Статусы заявки:

1. new — новая заявка;
2. contacted — клиенту ответили;
3. waiting_payment — ждём оплату;
4. paid — оплачено;
5. in_progress — услуга в работе;
6. completed — услуга завершена;
7. cancelled — отменена;
8. refunded — возврат.

Начислять баллы лучше после статуса completed или вручную после подтверждения админом.

MVP-правило:

> Баллы начисляются только после ручного подтверждения админом.

## 9. Пользовательский сценарий: клиент

1. Клиент заходит в бота.
2. Бот приветствует и показывает меню.
3. Клиент выбирает услугу.
4. Бот задаёт базовые вопросы.
5. Клиент оставляет контакт / подтверждает Telegram.
6. Бот создаёт заявку.
7. Админ получает уведомление.
8. Админ связывается с клиентом.
9. После оплаты и выполнения услуги админ подтверждает начисление.
10. Если клиент пришёл по реферальной ссылке, система начисляет бонусы по цепочке.

---

## 10. Пользовательский сценарий: партнёр

1. Пользователь открывает раздел SAFR Club.
2. Бот предлагает выбрать режим: Direct, Balanced или Network.
3. Пользователь выбирает режим.
4. Система создаёт реферальную ссылку и QR-код.
5. Партнёр делится ссылкой или показывает QR-код.
6. Новый клиент заходит по ссылке.
7. Система фиксирует связь.
8. После оплаты и подтверждения услуги партнёр получает Points.
9. Партнёр видит историю начислений.

---

## 11. Пользовательский сценарий: кафе / ресторан / байк-партнёр

1. Партнёр выбирает режим Network.
2. Система генерирует QR-код.
3. QR-код ставится в кафе, на стойке, у байков или у водителя.
4. Турист сканирует QR.
5. Попадает в бота / Mini App.
6. Видит услуги SAFR и возможность самому зарабатывать на рекомендациях.
7. Если турист становится активным и зовёт друзей, исходная точка получает бонусы в глубину.

---

## 12. Admin-сценарий изменения начислений

1. Админ открывает раздел “Услуги и начисления”.
2. Выбирает услугу, например “Виза”.
3. Видит текущие правила:
   - Direct: 2500 / 0 / 0;
   - Balanced: 1500 / 500 / 200;
   - Network: 500 / 500 / 500.
4. Нажимает “Изменить”.
5. Вводит новые значения.
6. Система закрывает старое правило valid_to.
7. Система создаёт новое правило valid_from.
8. Все новые заявки используют новое правило.
9. Старые начисления остаются без изменений.
