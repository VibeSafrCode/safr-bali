## Актуальные баги

### BUG-001 — После некоторых разделов меню текст не считывается как обращение

Статус: fixed
Коммит: 968e922 Fix service text waiting for consultation and housing  
Приоритет: высокий  
Дата: 2026-07-08

#### Симптом

Пользователь нажимает:

- `🏡 Найти жильё`
- `💬 Заказать консультацию`

Бот показывает нормальный текст раздела.

Но если пользователь после этого пишет обычный текст, например:

- `Привет`
- `Разобрать ситуацию`
- `Нужна вилла`

бот отвечает:

> Извините, я не понял, что вы хотите.

#### Причина

Не все разделы переводят пользователя в режим ожидания следующего сообщения.

Например, `💬 Заказать консультацию` показывает текст, но не кладёт пользователя в `SERVICE_WAITING_USERS`.

#### Что нужно сделать

Проверить `06 Development/bot/app/handlers/menu.py`.

Нужно пройти все основные сценарии:

- `💬 Заказать консультацию`
- `🏡 Найти жильё`
- жильё / видео / риски аренды
- `🛂 Сделать визу`
- конкретные визы
- `❓ А если нет всех документов?`
- `✍️ Написать человеку`
- `📋 Выйти в меню`
- `📋 Показать меню`

Ожидаемая логика:

- если раздел просит пользователя написать текст — включать ожидание текста;
- следующий текст должен уходить нужной группе;
- после отправки состояние ожидания должно очищаться.

### BUG-005 — Подтупливание бота и завершение диалога только со второго нажатия

Статус: fixed/deployed  
Приоритет: высокий
Дата фикса: 2026-07-09
Коммит: a130691  
Дата: 2026-07-08  
Где замечено: Telegram bot, клиентский режим диалога

#### Симптом

На двух аккаунтах замечено:

- бот иногда отвечает быстро, иногда с заметной задержкой;
- после первого нажатия `✅ Закончить диалог` визуально ничего не происходит;
- после второго нажатия `✅ Закончить диалог` бот “просыпается” и завершает диалог;
- после завершения появляется клавиатура:
  - `↩️ Вернуться в диалог`;
  - `🆕 Новый диалог`;
  - `📋 Показать меню`;
  - `🚨 Жалоба ГлавБоссу`.

#### Почему это важно

Пользователь может подумать, что бот завис или кнопка не работает.  
Для клиентского сценария это критично: режим диалога должен завершаться с первого нажатия.

#### Возможные причины

1. Конфликт handlers/FSM:
   - первое нажатие `✅ Закончить диалог` может попадать не в тот обработчик;
   - known-button защита может перехватывать текст кнопки раньше нужного handler;
   - активный state может мешать обычному handler завершения диалога.

2. Производительность:
   - `is_known_button_text()` может читать `menu.json` с диска на каждом сообщении;
   - runtime JSON-файлы могут часто читаться/писаться;
   - на слабом VPS это может давать задержки.

3. Дублирование/гонки Telegram:
   - пользователь быстро нажимает кнопку;
   - Telegram отправляет update, но бот обрабатывает его с задержкой;
   - второй клик приходит уже после смены состояния.

#### Что проверить

Файлы:

- `06 Development/bot/app/handlers/contact.py`
- `06 Development/bot/app/core/buttons.py`
- `06 Development/bot/app/handlers/menu.py`

Проверить:

- какой handler обрабатывает `✅ Закончить диалог`;
- не перехватывает ли кнопку `is_known_button_text`;
- какие состояния FSM активны после `✍️ Написать человеку`;
- очищается ли state после завершения диалога;
- вызывается ли `deactivate_dialog`;
- не создаётся ли несколько competing handlers на один и тот же текст.

#### Что сделать

1. Добавить точные логи на:
   - вход в режим `Написать человеку`;
   - первое сообщение клиента;
   - нажатие `✅ Закончить диалог`;
   - state до/после завершения;
   - какой handler сработал.

2. Оптимизировать `is_known_button_text()`:
   - не читать `menu.json` каждый раз;
   - закэшировать список кнопок в памяти.

3. Сделать обработчик `✅ Закончить диалог` максимально приоритетным:
   - он должен срабатывать до generic handlers;
   - он должен работать независимо от состояния пользователя;
   - он должен чистить FSM state и dialog state.

4. Проверить на двух аккаунтах:
   - первое нажатие завершает диалог;
   - повторное нажатие не требуется;
   - задержка исчезла или стала минимальной.



#### Результат фикса

Фикс задеплоен на VPS и проверен вручную.

Что изменено:

- добавлен in-memory cache для `known_button_texts()`, чтобы `menu.json` не читался на каждое входящее сообщение;
- добавлена ранняя обработка `✅ Закончить диалог` внутри `ContactHumanState.waiting_for_client_message`;
- теперь первое нажатие `✅ Закончить диалог` не теряется в FSM-handler;
- бот завершает диалог с первого нажатия;
- поведение проверено после деплоя на VPS.


#### Критерий готовности

- `✅ Закончить диалог` срабатывает с первого нажатия;
- бот отвечает стабильно быстро;
- в логах видно, какой handler обработал кнопку;
- нет лишней пересылки кнопки менеджеру;
- после завершения диалога пользователь видит корректное меню дальнейших действий.
