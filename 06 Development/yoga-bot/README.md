# Yoga Ganster Telegram foundation

Отдельный пакет для `@Yoga_ganster_bot`. Он не запускает SAFRWAY `app.main`, не открывает backend/БД и не запускает общие backfill, bridges или очереди. В этой поставке реализованы два явно выбираемых варианта первого запуска:

| `YOGA_MVP_MODE` | Возможности |
| --- | --- |
| `service_links` | RU/EN, страницы услуг на сайте, кнопка перехода в действующий SAFRWAY-бот к команде |
| `welcome_links` | RU/EN и ссылка на сайт |

Режим по умолчанию отсутствует. Выбор первого запуска и выпуск ведёт основная беседа проекта. Полный кабинет в Yoga, регистрация через общий backend, заявки, реферальная привязка, Points и начисления здесь **не реализованы**; это отдельный этап интеграции. Меню говорит об этом явно. Переход в основной бот идёт по обычной ссылке `https://t.me/<username>`, без `start`, клиентского сообщения или указания пригласившего. Далее действует существующий процесс SAFRWAY. Такая кнопка не обеспечивает привязку клиента к инфлюенсеру.

## Общий каталог

Единственный источник ссылок — каталог в `../shared/content`:

- `service-registry.v1.json`: устойчивые content IDs, legacy published routes, текущие candidate revisions и pins.
- `generated/i18n/public.v1.json`: названия опубликованных legacy страниц RU/EN.
- `registry-*-build.v1.json`: новые страницы только с `indexable: true`, явным actual PASS и всеми пятью `publicationGates: true`.
- `registry-copy/`: проверяемые SHA-256 body/metadata; кнопки получают только `h1` из одобренных metadata. Тексты и цены не отправляются в бот и не переписываются.

`sourceRevision` связывает текущий отрендеренный RU body с Registry. В full-payload пакетах `approvedSourceRevision` может означать другой pin исходного Markdown Founder; подменять им rendered revision нельзя. EN должен относиться к текущему rendered revision, иметь complete/QA и совпадать с projection pins. Черновики, старые revisions и непроверенные кандидаты не становятся новыми ссылками. Legacy published routes остаются самостоятельным основанием ссылки; это не дополнительная проверка фактической доступности услуги.

Меню включает услуги и навигационные hub/guide страницы, без самостоятельного меню knowledge/legal/trust статей. Кнопки ведут на настроенный Yoga origin и сохраняют канонические пути RU/EN. Каталог читается при старте процесса: обновляйте его вместе с сайтом и перезапускайте **только Yoga service** при очередном выпуске. Новая услуга с завершёнными gates появится без отдельной копии её текстов в боте.

## Offline проверка

Python 3.10+; проверено на 3.12. Установить `requirements.txt` в отдельный virtualenv и выполнить из каталога этого пакета:

```sh
python -m unittest discover -s tests -v
python -m yoga_bot.check_catalog --shared-root ../shared/content --site-origin https://yoga.example.org
```

`example.org` — только синтетический адрес для проверки. Тесты используют поддельный Telegram transport и синтетические IDs. Им не нужны токен, `.env`, сеть, сервер или браузер. Preflight проверяет каталог и URL, не читает environment и не обращается к Telegram. Успешный preflight не подтверждает, что URL доступен пользователям.

## Конфигурация оператора

Шаблоны: `deploy/yoga-bot.env.example` и `deploy/yoga-gangster-bot.service`. Секрет заполняется оператором через уже согласованный закрытый поток; не передавать токен в чаты, shell-команды, Git, AUDIT или журналы.

| Переменная | Значение |
| --- | --- |
| `YOGA_BOT_TOKEN` | Только токен Yoga; основное `BOT_TOKEN` игнорируется |
| `YOGA_MVP_MODE` | Один явно выбранный режим выше |
| `YOGA_SITE_ORIGIN` | Доступный клиентам HTTPS origin, без credentials/path/query/fragment; localhost/IP не подходят для ссылок в Telegram |
| `YOGA_MANAGER_BOT_USERNAME` | Username действующего SAFRWAY-бота без `@`; обязателен для `service_links`, отдельный от Yoga |
| `YOGA_SHARED_CONTENT_ROOT` | Абсолютный путь к согласованному каталогу текущего выпуска; runtime нужен только read access |
| `YOGA_RUNTIME_LOCK` | Отдельный `instance.lock`; шаблон использует `/run/yoga-gangster-bot/instance.lock` |

Постоянный домен не обязателен: оператор может выбрать уже доступный HTTPS адрес на существующей инфраструктуре. Убедиться, что выбранные RU/EN пути открываются и соответствуют выпущенному каталогу. Настройка origin сама по себе не публикует Yoga-сайт и не создаёт DNS.

## Выпуск и откат — для основной беседы

1. Получить выбор режима; зафиксировать ревизию пакета, canonical content revision, origin и public manager username. Проверить права на распространение выбранного сайта и возможность открыть ссылки с телефона. Секрет и его местоположение не включать в публичную запись.
2. Проверить владельца `@Yoga_ganster_bot`: остановить прежний Yoga poller, если он есть. [Telegram допускает одного long-polling потребителя для токена](https://docs.aiogram.dev/en/v3.13.1/dispatcher/long_polling.html). Локальный lock не обнаруживает процесс на другом сервере. Непустой webhook остановит запуск; runtime не вызывает `deleteWebhook` и не сбрасывает pending updates.
3. Подготовить отдельного непривилегированного Linux пользователя `yoga-bot`, отдельный virtualenv `/opt/yoga-bot/venv`, versioned package и ссылку `/opt/yoga-bot/current`. Исходники и public Registry принадлежат оператору и доступны Yoga только на чтение. Не давать Yoga доступ к основному environment, credentials или private files.
4. Подготовить `/etc/yoga-bot/runtime.env` через закрытый credential flow: root-owned, mode `0600`, содержащий только Yoga variables. systemd читает EnvironmentFile до смены пользователя. В шаблоне путь Registry с пробелом заключён в кавычки. Не выполнять `source`/`cat` этого файла в терминале.
5. Запустить offline preflight с тем Registry, который будет использоваться на сервере, и critical tests. Для новых страниц gate должен относиться к этому же выпуску. Сохранить предыдущие package revision и public Registry revision для отката.
6. Только после разрешения основной беседы установить отдельный unit и активировать `yoga-gangster-bot.service`. Первый live startup проверит `getMe`/`getWebhookInfo`; затем начнёт принимать реальные updates. Это отдельная от offline проверки операция.
7. Проверить состояние unit, фиксированные сообщения журнала, controlled `/start`, переключение языка, один service URL и кнопку команды на тестовом аккаунте оператора. Не писать клиентам. `runtime_ready` означает успешный preflight/identity check; подтвердить фактическую обработку update перед объявлением работоспособности. В этом пакете live проверки не выполнены.
8. Откат: остановить только `yoga-gangster-bot.service`, вернуть его previous package/Registry pair и перезапустить только его. Не менять SAFRWAY service, main environment, DB или очереди. У пакета нет миграций и данных, требующих rollback. Обновления, уже подтверждённые Telegram, не переигрываются автоматически.

Unit: отдельный User/Group и RuntimeDirectory, `UMask=0077`, защита файловой системы, без inbound HTTP listener. `RestartPreventExitStatus=2` предотвращает циклический запуск при неверной конфигурации, bot identity, webhook или конфликте polling. Временный сетевой сбой получает ограниченные повторы и exit `1` для штатного service restart. Exit `2` требует исправления причины оператором. При обновлении aiogram повторно проверить узкий polling override и transport tests.

## Обработка сообщений

Только личные чаты; группы, чужие targeted команды и callbacks к недоступным сообщениям игнорируются. За один проход выполняется один update без неограниченного создания задач. Ответы/изменения меню ограничены двумя в секунду, callback ACK имеет отдельный лимит пять в секунду на чат. Быстрое нажатие получает короткое подтверждение с просьбой повторить, когда изменение меню ещё ограничено; экстремальный burst сверх ACK лимита отбрасывается. Каталог имеет номера страниц, переходы вперёд/назад и возврат в меню. Локаль хранится только в памяти: максимум 2000 записей, действие preference истекает через час без активности; старая запись удаляется при следующем обращении, вытесняется по лимиту либо исчезает при остановке процесса. Регистрации клиента это не создаёт.

Неизвестные сообщения не пересылаются менеджерам и не записываются в хранилище. Пользователю прямо сообщается, что сообщение не передано; `/help` объясняет назначение меню. `/start` принимает только [Telegram payload syntax, максимум 64 символа](https://core.telegram.org/bots/features#deep-linking), затем отбрасывает параметр. Проверка синтаксиса не проверяет владельца referral ID и не выдаёт никакие права.

Логи содержат фиксированные коды (`runtime_ready`, `handler_failed`, `telegram_polling_owner_conflict`, `telegram_transport_retry` и т. п.), без токенов, IDs, текста сообщений, start payload, URL исключений и traceback. Код подавляет vendor exception logs, а polling конфликты и ошибки авторизации завершает с отдельным безопасным кодом. Клиентские документы и платежи в этот runtime принимать не следует: ссылки ведут в существующий процесс обслуживания.
